Rather than randomizing exit IPs per connection, Mullvad deterministically assigns them based on WireGuard public keys, which rotate every 1-30 days depending on client type. Testing 3650 different keys against 9 servers revealed all mapped to just 284 distinct IP combinations, not the trillions possible.

The root cause is a seeded RNG using the pubkey as seed: when you query random_range with the same seed but different bounds (pool sizes), you get the same underlying float value, which then scales to the new bounds. This means if user A gets IP at position 49/60 from server 1 and position 9/11 from server 2, the ratios are nearly identical (~0.81). Across all 284 combinations observed, IPs consistently land in the same percentile of their respective pools. The author created a tool estimating the float seed from observed IPs; if two accounts show overlapping seed ranges across different servers, there's >99% confidence they're the same user.

This enables correlation attacks: a forum moderator banning someone could identify their sockpuppet account using different servers by comparing IP log ranges, potentially deanonymizing users even behind the VPN. The author recommended avoiding server switching between pubkey rotations and forcing key rotation via app logout.
