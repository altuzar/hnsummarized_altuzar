The core insight: models like Kimi K3 (2.78T parameters) only activate ~4% of parameters per token. WARP keeps the shared "trunk" in RAM (27.28GB for K3) and streams only the selected expert layers from fast NVMe, using remaining RAM as a bounded expert cache.

Technical implementation: The container is optimized so each expert requires one aligned disk read. A lookahead router predicts needed experts for the next layer to overlap reads with computation. K3 uses 3-bit residual vector quantization for experts while sensitive weights stay at 4-8 bits. Its linear attention and compressed KV cache (0.21GB vs 11.25GB at 4K context) significantly reduce memory footprint. On a 64GB MacBook Pro M5 Pro, K3 achieves 0.45-0.62 tok/s; smaller models run much faster: DeepSeek-V4.1-Flash at 3.77 tok/s over 64 tokens, GLM-5.3-Flash at 3.32-3.86 tok/s, Kimi-Linear at 14+ tok/s. Conversion from published weights to the WARP format requires 1-2TB of temporary staging storage.

Performance insights: A 32GB machine can technically open K3 but pages heavily; 64GB is practical minimum. Surprisingly, beyond ~17GB expert cache on K3, throughput drops eightfold due to page faults despite higher hit rates—adding RAM isn't always faster. The engine is I/O-bound; one K3 token reads ~17GB of experts. On the tested machine's internal SSD (12.78 GB/s), throughput is acceptable; external USB enclosures (0.94 GB/s) are four minutes slower.
