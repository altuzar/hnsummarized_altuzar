The key innovation is an optimized calling convention that adds minimal overhead in the normal case while catching abuse.

The core design passes two implicit arguments to every function: a thread pointer (my_thread) and a function capability (function_object). These are passed in registers alongside normal arguments. For well-behaved calls with matching signatures, arguments and return values flow through registers almost identically to a native ABI—the only difference from "Yolo-C" is the two extra arguments and a one-bit exception flag in the return.

The implementation uses three layers of optimization. The generic calling convention (the safety net) moves arguments through thread-local CC buffers (one for payload data, one for capability pointers) and performs full capability checks. The register calling convention adds signatures encoded as 64-bit integers. Each function object contains: a fast_entrypoint pointer (register-based native ABI), a generic_entrypoint pointer (CC-buffer based), and a 64-bit signature hash. At callsites, code checks if the observed signature matches the expected one; if it does, the fast path is taken. If not, weak thunks are generated (linkonce_odr, resolved by the linker) that translate between the two calling conventions—a caller thunk moves arguments from registers to CC buffers and calls generic_entrypoint, while a callee thunk does the reverse.

The signature encoding handles up to 16 arguments and 2 return values of types: integers (64-bit), float, double, long double, 128/256/512-bit vectors, any pointer, plus three reserved types (11 types total). The scheme encodes both the types and the length of the sequence into a single 64-bit value, leaving substantial room for future extensions. Example: char* (*)(int, char*, double) encodes as 60125, where char* (pointer) = 7, int = 0, double = 2, giving Ret = 1+7 = 8 and Arg = 1+11+121+0+7*11+2*121 = 452, so 1+8+133*452 = 60125.

The third optimization avoids linker resolution entirely for direct calls. Instead of calling a getter to resolve the symbol, the compiler emits code that calls a signature-mangled implementation name directly (e.g., pizlonatedFI60125_foo for foo with signature 60125). If the definition matches in the same module, this works directly with no overhead. If the definition is extern or has a different signature, a weak callsite thunk with the same mangled name is locally defined, which performs the full resolution, capability check, and gateway between fast and generic calling conventions.
