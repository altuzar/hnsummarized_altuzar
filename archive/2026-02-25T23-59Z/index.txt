12:Te9e,Google explicitly instructed developers for years that API keys (AIza... format) are safe to embed in client-side code like Maps embeds. These keys were designed as project identifiers for billing and access control, not authentication credentials. They could be restricted by HTTP referer or API allowlists—mechanisms that assumed the worst case was denial-of-service, not silent privilege escalation.

Then Gemini launched. When a project enables the Generative Language API, every existing API key in that project—including the years-old Maps keys sitting in public JavaScript on websites—silently gains full access to Gemini endpoints. No warning, no confirmation dialog, no email. An attacker can trivially scrape the key from public page source and then: access uploaded files and cached data via /files/ and /cachedContents/ endpoints, run up massive usage charges on the victim's account (thousands of dollars per day is feasible), or exhaust quotas to disable the victim's legitimate services.

Truffle Security scanned the November 2025 Common Crawl dataset and identified 2,863 live Google API keys vulnerable to this vector. Victims included major financial institutions, security companies, Google itself (with keys deployed since February 2023), and unknowing developers following Google's own guidance. The disclosure timeline shows Google initially dismissed the report as "intended behavior" on Nov 25, but after being provided examples from Google's own infrastructure, they reclassified it to a "Bug" and "Single-Service Privilege Escalation, READ" by Jan 13.

The core issues: (1) Single key format serves dual purposes—public identifier and sensitive credential—violating secure API design principles. (2) Insecure defaults: new keys created in GCP default to "Unrestricted," valid for every enabled API including Gemini. (3) Retroactive privilege expansion: keys deployed safely years ago under documented guidance became dangerous without any developer intervention or notification.

Google's announced roadmap includes scoped defaults for AI Studio, leaked key detection/blocking, and proactive notifications. However, these are forward-looking fixes that don't retroactively protect existing exposed keys or notify impacted customers.
