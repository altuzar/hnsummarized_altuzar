A minimal example—spawning a background task without awaiting—produces outputs: ABC (Trio), AB (Smol), AC (Swift), C (JavaScript), A (Asyncio), A (Rust), ACB (Tokio). No two runtimes agree on all three variations of this program.

The authors identify nine design dimensions across three lifecycle phases. Start of Life covers Eagerness (lazy vs eager function evaluation) and Suspension Guarantees (static vs dynamic suspend points). End of Life covers Extent (indefinite vs dynamic task lifetime), Reference Strength (strong vs weak runtime references), Destruction (awaited vs cancelled vs terminated cleanup), and Exception Propagation. Cancellation covers Awareness (can tasks respond?), Direction (top-down, bottom-up, or simultaneous), and Persistence (transient vs persistent cancellation). For example, Swift uses Dynamic Extent with Cancellation Destruction (tasks die at scope end), while Trio uses Dynamic Extent with Awaited Destruction (tasks wait to finish).

The paper formalizes these choices in a core calculus with step-by-step execution traces showing exactly where runtimes diverge. They map each language to its design choices and note C++ doesn't fit—every axis is configurable, making knowledge transfer between projects difficult.

The type existed internally but was unstable until August 2024 when contributor waffle stabilized it in Rust 1.100.

The stabilization involved a thorny backward-compatibility problem. Prior to 2024, when the compiler couldn't infer a type during type inference, it would fall back to () (unit type).
