12:Tbe0,Dmitry Brant helped an accounting firm migrate away from legacy RPG II software running on Windows 98 through a parallel-port hardware dongle. The dongle was manufactured by Software Security Inc in the early 1990s and was required by both the RPG compiler (RPGC.EXE) and any executables it generated.

Brant disassembled the protection code using Reko and found it in a separate x86 segment (0800). The routine performs a series of writes and reads to the parallel port's data and status registers, accumulating results in CPU registers BH and BL, then returns via RETF. Crucially, the routine takes no inputs—meaning it returns a constant value. Through inspection, he determined BH must always be 0x76, leaving only BL unknown. A simple brute-force loop testing all 256 possible BL values revealed the magic constant: 0x7606. He patched the routine to simply set BX to this value and return, eliminating the dongle requirement. Since the compiler copies this routine into compiled binaries, the patch propagates automatically.

The comment section enriches this with historical context. weinzierl recalls accidentally mixing up dongles in an early 1990s PCB design lab. Several commenters (ruleryak, giamma) describe even simpler cracks from that era—finding and flipping conditional jump instructions, modifying hardcoded trial limits in hex editors. dehrmann argues the protection was actually appropriate for its time, requiring specialized tools and knowledge to defeat. userbinator notes Reko's failure to decompile was likely because the segment was hand-written assembly (I/O instructions have no C equivalent), echoing a classic pattern.
