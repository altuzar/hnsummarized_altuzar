The core insight is that LLM inference during token generation (the "decoder pass") is fundamentally memory-bound, not compute-bound—the CPU sits idle waiting for weights to cross the memory bus, making this more tractable on CPU than one might expect.

The solution involves activating 25 largely undocumented optimization flags in ik_llama.cpp (a specialized fork). Key techniques: Speculative decoding pairs a large verifier with a tiny drafter whose weights fit in L3 cache, exploiting that extra CPU cycles are cheap relative to streaming verifier weights. MoE-specific flags (--cpu-moe, --merge-up-gate-experts) optimize for CPU cache hierarchies to prevent "cache thrashing" when jumping between 128 experts. Memory pinning (--mlock) prevents the OS from swapping 27GB to disk. Runtime repacking reorganizes weight matrices to match CPU cache layout. Flash Attention—originally GPU-only—is ported to CPU by ik_llama, fusing softmax with matmuls to keep the attention matrix in fast local cache rather than materializing it to RAM. Multi-Head Latent Attention compresses the KV cache. The setup achieves an 82GB memory footprint (25GB weights, 56GB KV cache at 262K context) and generates text at approximately 12 tokens per second.

The post frames this as a challenge to the "usability moat" of black-box tools (ollama, standard llama-cpp) that hide performance levers and bake in poor defaults. The "alternative" divides by 256 with a +0.5 offset, placing each value at the midpoint between integers, avoiding extreme values and improving theoretical quantization error (1/1024 vs 1/1020 mean absolute error). However, both methods have trade-offs.

The standard formula's main weakness: when converting back from [0,1] floats to integers, the extreme bins (0 and 255) are effectively half the width of middle bins, making uniform random noise 50% less likely to produce pure black/white. The alternative avoids this asymmetry and yields exact fractions (128/256 = 0.5), but it doesn't actually use the full [0,1] range (starts at ~0.002), complicating zero-detection in image processing and tying logic to 8-bit limits.
