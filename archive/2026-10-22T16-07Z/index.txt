12:Tc55,PHP released security patches on October 21, 2026 for two critical vulnerabilities affecting all supported versions (8.2-8.5). Both allow unauthenticated remote code execution with CVSS 9.2 severity.

CVE-2026-109618 (RCE via OOM corruption): Out-of-memory handling interrupts PHP while internal request data is only partially initialized, causing cleanup to treat invalid data as valid. CVE-2026-109619 (RCE via stale global state): Request-owned internal state survives after backing memory is freed, allowing later requests in the same worker to use stale state before normal initialization resets it. Affected deployments include PHP-FPM, Apache mod_php, php-cgi, FrankenPHP, and LiteSpeed. The advisory notes mod_php carries highest risk since exploits trigger before any application code runs.

The PHP team provided minimal backports for EOL versions 7.4, 8.0, and 8.1 to assist those unable to upgrade. For those unable to patch immediately, limited mitigations exist: for OOM corruption, setting memory_limit=-1 at the server level (not per-app), restricting post_max_size, using container limits, and enforcing web server request size limits. For stale global state, disabling session.upload_progress and restarting workers, setting fatal_error_backtraces=0 on PHP 8.5, and removing per-request settings that emit diagnostics. The advisory explicitly states these do not make installations safe—only patching does.

The six TLS intermediates (DV, OV, EV in two generations) and two code-signing CAs were all cross-signed by Sectigo. They existed undetected for 17 months before October 2026 disclosure. Google's paranoid_crypto fuzzer found this while testing the CCADB certificate corpus.

What matters for exposure: Chrome and Firefox blocked these intermediates directly and require Certificate Transparency (CT), which prevented mis-issued TLS certificates from being trusted by default in browsers. Safari also requires CT. However, the non-browser ecosystem is vastly larger and more vulnerable. Default settings in curl, Python, Node, Go, Java, git, and package managers do three things that enable attack: they trust a disk CA bundle, don't check revocation, and don't check CT. Only Windows CryptoAPI caught revocation, and only partially.
