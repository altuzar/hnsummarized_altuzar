Unsatisfied, Moertel researched the 6809 microprocessor manual and discovered PSHS (push registers to stack) and PULS (pull from stack) instructions that could move multiple bytes in few cycles.

The core insight: use S and U stack registers as source/destination pointers, loading/storing via D, X, Y registers. Then load the DP (direct page) register as a seventh byte go-between. This allowed copying 7 bytes per PULS/PSHU pair—and crucially, 14 (tile width) is divisible by 7. The 5-instruction row-copy code ran in 56 cycles, versus friend's 98.

The mangling problem: pushes/pulls reverse order (stack grows downward), so septets got swapped and rows inverted during copying. Solution: pre-process tiles once to reverse their septet order; the two reversals cancel.

The interrupt corruption problem: when audio interrupt fired during tile-copying, the processor pushed state onto the system stack (S register), which was pointing into the tile reference buffer. Solution: swap which register points where (U to tiles, S to screen buffer), so corruption happens only to temporary screen data. Then reverse draw order (bottom-right to top-left) so the next tile drawn immediately overwrites corrupted pixels before display refresh.

Final performance: 1689 cycles versus friend's 2893—70% speedup, crossing the perceptual threshold from choppy to smooth.
