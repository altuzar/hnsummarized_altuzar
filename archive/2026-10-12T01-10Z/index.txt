It provides agents with tools to inspect running programs, extract decompiled code, trace function calls, and explain software behavior. Users describe what they want to understand in plain English—for example, "Why does Windows Calculator give 220 for 200 + 10%?"—and the agent analyzes the target, returns relevant code excerpts and values, then interprets and explains the findings.

The linked page demonstrates REA through two interactive examples. The Chrome dinosaur game example shows recovery of the game's acceleration rule (starts at speed 6, increments by 0.001 per frame up to 13). The Calculator example reverse engineers the percentage button handler, discovering that after addition it calculates 10% of the first operand, but after multiplication it treats 10% as 0.1. Both examples include working reconstructions where users can test the recovered behavior.

REA supports native binaries (assembly analysis), JavaScript/Electron apps (code extraction from disk), and browser debugging. Setup requires copying a prompt into a compatible agent and running `npx rea-agents@latest setup`. The tool leverages existing MCP servers (Ghidra, IDA Pro, browser debugging protocols) rather than reimplementing reverse engineering infrastructure.

The first flaw: semicolons in URL query parameters are never escaped, so a crafted link like tg://x?a=1;CMD:quit gets flattened as OPEN:tg://x?a=1;CMD:quit; and the receiver splits it into two separate commands at every semicolon, enabling command injection.

The second flaw exploits this injection to trigger an internal interpret: URI scheme originally designed for Telegram's release automation. This scheme invokes InterpretSendPath, which reads arbitrary files specified in an instruction file and uploads them to a chat with zero authorization checks or confirmation dialogs. Combined, an attacker can inject OPEN:interpret:path/to/file commands, exfiltrating any file.

The attack in practice: attacker creates a supergroup, adds the victim, sends three instruction text files that get auto-downloaded to the Downloads folder, then sends an innocuous https link that redirects to a crafted tg:// URL with three injected interpret: commands. Clicking the link steals key_datas, the session authorization file, and the account index. Since Telegram uses no local passcode by default, the salt stored in key_datas is enough to derive the key encryption key, decrypt the session file, and take over the account.
