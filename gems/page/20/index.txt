12:T9c0,Tim Wehrle documented storing an entire website inside a favicon by encoding HTML into pixels. Each pixel's RGB channels store three bytes sequentially; a 4-byte header specifies payload length to handle unused trailing pixels. His 208-byte HTML payload fit into a 9×9 pixel (81-pixel total) PNG, using 87% capacity. The browser reads the favicon via canvas API, reverses the byte extraction, and JavaScript reconstructs the original HTML to replace page content via a "Render Website" button.

The project necessitates a bootstrap loader—the favicon alone is just a PNG without JavaScript to decode it. This makes the approach impractical compared to traditional content delivery, yet it validates the concept within severe constraints.

Local port forwarding (-L) forwards a remote service to a local port, useful for accessing private databases or loopback services through a bastion. The command structure is ssh -L [local_addr:]local_port:remote_addr:remote_port [user@]sshd_addr. Labs demonstrate accessing a loopback-only web service, accessing VPC services through a bastion, and using -J ProxyJump to reach remote loopback ports (debug endpoints, metrics) through an intermediate host.

Remote port forwarding (-R) exposes a local service on a remote port, requiring GatewayPorts yes on the SSH server. Demonstrates exposing home network services through a public gateway for external access. Labs show local loopback services and home network devices becoming accessible remotely.

Dynamic forwarding (-D and -R with no destination) turns the SSH client or server into a SOCKS proxy, avoiding the need for separate tunnels per destination. The -D flag creates a local SOCKS proxy reaching any host accessible from the remote machine.
