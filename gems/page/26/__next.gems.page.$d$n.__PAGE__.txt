2c:Tf37,Dmitry.GR has completed a comprehensive reverse-engineering and preservation effort of Fisher-Price/Mattel's Pixter gaming console line (2000-2005), covering Pixter Color, Pixter Multimedia, Pixter Classic, and variants. The effort includes full documentation, emulation, and Wikipedia/Internet Archive updates. The project focuses on understanding the hardware and games from scratch, as no official documentation existed.

Starting with Pixter Color, Dmitry identified the main SoC as a Sharp LH75411 ARM7 in LQFP package (fortunate, because this enabled pin probing). The board contained minimal support: 128KB external SRAM, 16KB TCM in the SoC, no cache, no MMU, no MPU—a radically cost-reduced ARM design. He initially found almost no recognizable ARM code in dumped game ROMs, leading to investigation of the system ROM housed in an epoxy blob. By leveraging the cart slot's exposed pins and carefully desoldering three control pins from the minimally-cooperative SoC, he successfully dumped the 2MB blob ROM using a Pi Pico 2.

Analysis of the ROM revealed the core innovation: a 16-bit stack-based virtual machine implementing game logic. The VM is brutalist in design—unbalanced stack operations (pushes/pops), 32-bit values despite being "16-bit," no overflow protection, executing at roughly 4MIPS on this slow processor. Opcode analysis suggests the VM was originally designed for a 16-bit architecture and later ported to ARM without structural changes. The VM includes high-level Pixter-specific opcodes for drawing, touch handling, and sound playback. Despite this work, background music was mysteriously absent from emulation.

Tracing the motherboard revealed a second epoxy blob connected only to the audio amplifier and a cart pin. This was a melody chip producing MOD-like sample playback. The Pixter's audio output itself was bizarrely implemented: two PWM units in the SoC, each 7-bit, were repurposed such that positive samples drove PWM0 (fed to the amp's positive input) while negative samples drove PWM1 (inverted, fed to the negative input). This yields only one extra bit of resolution at high complexity and suggests fundamental misunderstanding of PWM or audio amplification.

Dmitry extended his uARM emulator with LH75411 support, emulated the resistive touchscreen ADC, implemented the VM interpreter, and built a working Pixter Color emulator. He dumped game carts using a multi-pass approach (low/high bytes separately due to pin constraints) and similarly reverse-engineered Pixter Classic (a distinct, older device using a different SoC and architecture), Pixter Multimedia, and others. Each variant required unique approaches: Pixter Classic used a different VM with different instruction opcodes; later variants introduced NAND flash carts and wireless features.

The linked page provides detailed technical documentation: VM instruction sets, cart header formats, pinouts, memory layouts, compression schemes, and preservation file formats. Dmitry has released disassemblers (ClassicDisasm, ColorDisasm), emulators (uPixter, uARMpixter), and other tools.

The motors have excessively high KV (335 vs 90 needed), so Musa manually rewound each motor using single-strand 24 AWG wire to achieve 40 turns/slot instead of the factory's 22 turns/slot, switching from delta to star winding.
