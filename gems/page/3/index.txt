Publicly playable servers exist on EU and US infrastructure.

The implementation is roughly 5900 lines of SQL (compared to 9000 in original C code), excluding comments. The architecture separates game logic (fixed 35 Hz loop) from rendering (on-demand framebuffer generation). Doom's .wad file format loaded in ~18 seconds. Game state lives in SQL tables; each tic calls a procedural function that executes sequential SQL updates modeling Doom's AI, physics, weapon systems, and effects. The renderer is a single massive query with 89 CTEs that replicate Doom's rendering pipeline: BSP tree traversal for occlusion ordering, wall rendering by columns, visplane computation (floors/ceilings) using window functions, sprite handling, and Z-buffering via priority encoding.
