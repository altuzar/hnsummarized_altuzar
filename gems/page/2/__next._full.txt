2b:Tc97,A single transformer block, reused 2-4 times with shared weights (looped transformer), runs as a world model on a Pico 2 W microcontroller. Given a game frame and button press, it outputs the next frame and reward. A separate 9k–16k parameter MLP actor network selects actions from the generated frames. The setup proves you can fit both world models and agents on tiny hardware.

Frame representation splits into tokens (patches of 2×2 to 6×6 cells depending on game size), with learned position embeddings inside patches. The transformer applies one attention block plus ReLU MLP multiple times; increasing loop count trades speed for accuracy—most games use 2 loops for playable framerates. Decoding from model outputs uses three rules: background cells pick their highest-scoring token independently; singletons (balls, player, ghosts) get placed once globally to prevent duplicates; multi-cell sprites use their state cell and stamp the rest. This three-rule decode matters almost as much as the model itself.

Five games tested: Breakout (26k params, 99.99% exact frames), Pong (46k params, 99.45%), Flappy Bird (46k params, 100%), Doom-lite (55k params, 83.6%), Pac-Man lite (131k params, 86.4%). Lower percentages on 3D/complex games reflect stricter per-cell matching; game state is nearly always correct. Each fits in 361–600 KB flash. Training uses 1–3M recorded gameplay transitions, then quantization-aware training (QAT) with int8 weights and float embeddings/scales. The exported int8 model is verified bit-for-bit against Python integer spec.

The actor network learns via Stream-X (Elsayed et al.), an eligibility-trace RL algorithm needing no replay buffer or target networks. It observes hand-crafted features (ball position/heading, ghost distances, etc.), runs a two-hidden-layer MLP with LayerNorm. Early training happens on real games, later rounds fine-tune in the dreamed world to close exploits agents find. Agents reach near-max scores: Breakout 45.6/56, Pac-Man 217.4/249, Doom-lite 82.9, Flappy Bird 332, Pong 1.1 (note: Pong reward is relative).

On the Pico, core 1 runs the game loop: actor picks action from frame features, int8 transformer runs 2 loops, decoder produces next frame, learner updates if enabled (50 KB eligibility traces). Core 0 handles USB and optional ST7789 display. Matmuls use SMLAD instructions (2 MACs per clock). The same int8 engine compiles to WebAssembly with no dependencies; wasm dreams frames at 1–5 ms per game, matching native output frame-for-frame.
