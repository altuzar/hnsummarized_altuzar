He spent months on development after completing From NAND to Tetris and building a CHIP-8 emulator. The emulator features sound, runs on desktop (via Raylib) and web (via Fable transpilation), with a clean interface: a framebuffer array, audio buffer, stepEmulator function, and joypad state callback.

The CPU implementation showcases F#'s discriminated unions for modeling instructions. Rather than 512 distinct opcodes, Kossolapov generalized them to 58 instruction types using From/To location types, eliminating illegal states through the type system. For example, Load instructions only allow reading from immediate/register/indirect and writing to register/indirect, preventing nonsensical operations. He notes one compromise: opcode 0x76 technically maps to Load(Indirect, Indirect), an impossible operation handled as HALT. The functional Flags module using piped bit operations eventually replaced a more complex DU-based flag setter, improving performance by 10%.

The PPU implementation proved mechanically challenging. Kossolapov started by rendering tiles and backgrounds directly to screen, then incrementally added sprites and scrolling. A major accuracy trade-off: the real Game Boy uses pixel FIFOs matching CRT behavior, but the emulator renders entire scanlines at once, which works for most games but breaks on edge-case hardware exploits.

The joypad controller revealed subtle hardware interactions: the register changes between CPU reads, and games rely on reading it multiple times to access all buttons. Initial caching broke this, requiring the IoController to update the joypad register only on CPU read.

Sound proved the most conceptually difficult. Kossolapov initially tried dynamic sampling rates driven by framerate (counter-intuitive), causing audio pops on different platforms. Switching to audio-driving the emulator eliminated race conditions and platform quirks. He chose 32768 Hz sampling (one sample per 128 CPU cycles, divisible by 4) for clean alignment with CPU instructions. Audio remains the "leakiest" part of the emulator-frontend interface due to sync precision requirements, and he's not entirely satisfied with the current implementation.

The Fable transpilation initially produced incorrect code: bitwise operations on uint8 weren't truncated in JavaScript's 32-bit semantics, causing registers to hold invalid values like -15565461. Reading Fable's transpiled JavaScript directly revealed the issue; after fixing truncation, the web version worked perfectly with a 100 kB bundle.

Performance optimization came through profiling. The MemoryRegion discriminated union's mapAddress function created millions of heap allocations per second and excessive JIT branching.
