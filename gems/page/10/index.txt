2b:Tb54,The article walks through classic data compression techniques with interactive demos. Run-length encoding (A9B4C2D1A3D9) shows basic redundancy removal. Arithmetic coding encodes entire datasets as single fractional numbers by iteratively subdividing ranges according to symbol probabilities. Huffman coding builds decision trees assigning shorter bit-patterns to frequent symbols. The key insight: **entropy is a floor—the minimum bits-per-symbol for lossless data, given a probability distribution**, calculated as −log₂(P).

The breakthrough comes when introducing context: using order-1 models (probabilities conditioned on previous symbols) cuts "TO BE OR NOT TO BE" from 2.59 to 1.16 bits/symbol. Language models do exactly this—predict next-token probabilities from context—and feed those to an entropy coder. A well-trained LLM assigns high probability to the actual next token, minimizing bits; poor guesses cost more bits. The article cites a 2023 DeepMind paper claiming language modeling and compression are "two views of the same thing."

**Commenters add critical nuance:**

Several experts note this isn't new. Cambridge's MacKay taught this as unified information theory + ML; 3Blue1Brown and Schmidhuber have explored similar frames. One commenter credits "Compression is Intelligence" as the underlying principle since the 1960s.

**Sharp disagreements emerge:**

A top comment argues the article uses "proportion" (measured fact) not prediction, and "evaluation" not prediction. Knowing only that one character dominates, without exact frequencies, gets you to ~11 bits—prediction isn't required. The technique exploits the fact that address protections (SMEP, SMAP, IOMMU page tables, access control) operate on physical addresses from the CPU's perspective, but the memory controller performs a final address remapping before reaching actual DRAM.
